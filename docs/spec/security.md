# Security requirements: single source of truth

> Derived from the 12-check read-only audit in Nelson Lee's "Security Checklist for Vibe Coded
> Apps" [article 006], plus agent- and localhost-specific risks. Each requirement has a **verification**
> (test or gate) and an **owning card**. The M1 exit gate (M1-20) runs the 12-check audit prompt in
> `docs/harness/prompts/security-audit.md` against the code, with three-state PASS / FAIL / NOT FOUND
> results and file:line evidence.

| ID | Requirement | Verification | Owner |
|---|---|---|---|
| **SEC-01** Object-level auth | Single-owner DB (ADR-016): every route except `GET /healthz` and `POST /auth/login` requires auth, and every route declares a scope (api-rest §0). Routes are registered only through `defineRoute({method, path, scope, handler})`, which records metadata | Test `route-inventory.test.ts`: every entry in `app.routes` (except the two public ones) has registry metadata with a scope. A route without a scope fails CI | M0-07, M0-08 |
| **SEC-02** Rate limiting | Token buckets per api-rest §14 (login per IP + lockout, capture, imports, global) | Test: 6th login in 60 s → 429 with `Retry-After`. 31st capture/min → 429 | M0-08 |
| **SEC-03** Password storage | argon2id via `@node-rs/argon2` (library defaults ≥ OWASP: m=19 MiB, t=2, p=1). Password ≥ 12 chars. No other algorithm anywhere | Test: stored hash starts `$argon2id$`. Grep gate: no `md5`/`sha1`/`createHash('sha256')` applied to passwords | M0-08 |
| **SEC-04** Session revocation | Sessions and tokens live server-side, stored **hashed** (sha256), each individually revocable. Logout revokes the session. `jm reset-password` revokes all sessions. Session 14 d sliding, token default 365 d | Tests: revoked token → 401. Logout → old cookie 401. Expired session → 401 | M0-08, M0-11 |
| **SEC-05** Secrets in repo | `.env*` gitignored (only `.env.example` tracked). The data dir lives outside the repo. Fixtures and seeds are **synthetic only** (no real contacts) | `pnpm verify:full` runs `scripts/secret-scan.ts` over tracked files: `jm_[A-Za-z0-9_-]{20,}`, `sk-[A-Za-z0-9]{20,}`, `-----BEGIN .*PRIVATE KEY`, `AKIA[0-9A-Z]{16}`, `xox[bp]-`. Any hit fails | M0-14 |
| **SEC-06** Client-side exposure | The web app authenticates **only** by the HttpOnly cookie. Nothing auth-related goes in `localStorage`/`sessionStorage`. The SPA bundle contains no keys | Gate: grep `apps/web/src` for `localStorage`/`sessionStorage` (must be 0 hits for auth). Grep `apps/web/dist` for `jm_`/`sk-` | M0-12, M0-14 |
| **SEC-07** Transport | Bind `127.0.0.1` by default. A non-local `--host` requires `JM_PUBLIC_URL=https://…` (TLS proxy) or the explicit `JM_INSECURE_OK=1`. Cookies get `Secure` when served over https. HSTS when https. `secureHeaders()`: CSP `default-src 'self'; frame-ancestors 'none'`, `nosniff`, `Referrer-Policy: no-referrer` | Tests: default config binds 127.0.0.1. Response headers present on `/` and `/api/v1/*` | M0-07, M0-08 |
| **SEC-08** Data at rest | Tokens and sessions are hashed. **M2:** provider API keys encrypted at the application layer (AES-256-GCM, `JM_ENCRYPTION_KEY`, 32 bytes base64). **Honest gap:** contact names and emails are plaintext in v1. Host disk encryption does **not** count, and the README says so. Optional field encryption is an M7 item | Test (M2): the DB row for a provider key does not contain the plaintext key | M2-02; README in M1-20 |
| **SEC-09** Input handling | DB access via Drizzle query builders or `sql` templates with bound params only. `sql.raw` is allowed only in migrations. The server never builds shell commands (`child_process` is banned in `apps/server/src`). Captured HTML is converted to text server-side, and the web renders JD/profile text as **plain text** (no `dangerouslySetInnerHTML`). File uploads (M2) are MIME-sniffed, capped at 10 MB and stored under generated names | Gates: grep `sql.raw` outside `packages/db/migrations`, grep `child_process` in `apps/server/src`, grep `dangerouslySetInnerHTML` in `apps/web/src`. Each must be 0 | M0-14 (gate), all cards |
| **SEC-10** Abuse surface | No public signup and no unauthenticated setup route (`jm init` is local). Unauthenticated routes: `/healthz`, `/auth/login` (rate-limited), static SPA assets | Covered by the SEC-01 inventory test | M0-07 |
| **SEC-11** Paid-call abuse (LLM) | M2: every LLM-calling route requires `write`, is rate-limited, and checks `llm_usage` against `llmDailyBudgetUsd` before calling. Batch operations show an estimate first (cost-preview gate, like Voidscape's preview) | Test (M2): over budget → 429 `rate_limited` with `details.reason='llm_budget'` | M2-03 |
| **SEC-12** No paths from requests | The server never opens a filesystem path taken from request input. Imports are posted as content | Code review + grep for `fs.` usage in route and service files outside `tasks/` and `shared/storage` | all cards; audit in M1-20 |
| **SEC-13** SSRF-safe fetch | `safeFetch(url)`: http/https only, ports 80/443, DNS-resolve and reject private, loopback, link-local, CGNAT, multicast and IPv6 ULA ranges, re-check every redirect (≤3), 10 s timeout, ≤2 MB, `text/html`/`application/json` only. Used by capture (M1) and discovery (M5) | Unit tests with a mocked resolver: `127.0.0.1`, `10.x`, `169.254.169.254`, `[::1]`, and a redirect to private → all rejected | M1-09 |
| **SEC-14** Prompt-injection hygiene | JD, profile, import and email text is **untrusted data**. It is marked `content_trust: "untrusted"` in MCP output. LLM prompts (M2) put it in delimited data blocks, the analysis calls get **no tools**, and every LLM output is parsed by a Zod schema (invalid → retry once → fail) | MCP tests assert the marking. M2 eval: a JD containing "ignore previous instructions" doesn't change the output schema or add actions | M1-13/14/15, M2 |
| **SEC-15** CORS | No CORS headers by default (the SPA is same-origin). `JM_CORS_ORIGINS` allowlists exact origins (the M3 extension's `chrome-extension://<id>`). Never `*` | Test: a cross-origin preflight without allowlist → no `Access-Control-Allow-Origin` | M0-07, M3 |
| **SEC-16** Dependencies | Lockfile committed. The allowlist in `docs/harness/CONVENTIONS.md` is enforced: **implementers never add packages**, only the orchestrator does, after review. `pnpm audit --prod` runs in CI and on demand **with confirmation** (it contacts the registry, per the dependency-security-scan skill) | CI job. Gate: a `package.json` diff in an implementer PR fails review | M0-03, M0-14 |
| **SEC-17** CSRF | Cookie-auth mutations pass Hono `csrf()` (Origin must equal the server origin). Bearer requests are exempt | Test: cookie POST with a foreign `Origin` → 403 | M0-08 |
| **SEC-18** DNS-rebinding protection | Requests whose `Host` header isn't in the allowed list (`127.0.0.1:<port>`, `localhost:<port>`, `JM_PUBLIC_URL` host) are rejected with 421/400, on **all** routes including `/mcp` (the MCP spec's local-server warning) | Test: `Host: evil.example` → rejected | M0-07 |
| **SEC-19** Audit trail | Login success/failure, token create/revoke, imports and exports write `activities` (actor + summary, never secrets) | Tests in M0-08 and M1-11/12 | M0-08, M1-11, M1-12 |
| **SEC-20** MCP blast radius | No delete tools. Write tools need the `write` scope. `/mcp` requires bearer auth (no cookie) | MCP test: `tools/list` contains no name matching `delete\|remove_all` | M0-10 |
| **SEC-21** Export/backup PII | Exports exclude `password_hash`, `sessions` and `api_tokens`. Backups stay in the data dir. The docs warn that exports hold third-party PII | Test on `/exports/json` keys | M1-12 |

## Evidence rule (all audits and verifier reports)
Every check reports **PASS, FAIL or NOT FOUND**, with `file:line` evidence. Never report PASS without
evidence. If the evidence can't be found either way, report NOT FOUND. Mark anything that was
inferred rather than verified as `(inferred)` [articles 006, 007].
